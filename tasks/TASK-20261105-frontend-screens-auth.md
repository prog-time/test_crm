## Что делаем
Делаем интерфейс мини-CRM: вход по email и паролю, защищённые маршруты, layout с учётом роли и все экраны из ТЗ (2.5): список объектов, карточка объекта, карточка задачи с действиями и историей, «Мои задачи». UI показывает только действия, доступные текущему пользователю в текущем статусе. Это дублирует правила базы для удобства, но не заменяет их.

## Пользователь получает
Как **постановщик**, я могу **вести объекты, создавать и редактировать задачи, принимать работу или возвращать её на доработку с комментарием**, чтобы **управлять работами на стройках**.
Как **исполнитель**, я могу **видеть свои задачи, фильтровать их по статусу и брать в работу / отправлять на проверку**, чтобы **вести свою работу без лишнего**.

## Готово когда
- [ ] Given неавторизованный пользователь, when он открывает любой защищённый маршрут, then его перенаправляет на `/login`; после входа по email и паролю он попадает на стартовый экран своей роли
- [ ] Given неверный пароль, when пользователь отправляет форму входа, then видит понятную ошибку; регистрации в UI нет
- [ ] Given постановщик, when он открывает список объектов, then может создать, отредактировать и удалить объект; when объект с задачами нельзя удалить, then видит понятное сообщение об ошибке из базы
- [ ] Given исполнитель, when он открывает список объектов, then видит только объекты со своими задачами и не видит кнопок создания, редактирования и удаления
- [ ] Given карточка объекта, when её открывает постановщик, then видит все задачи объекта со статусами и форму создания задачи (название, описание, обязательный исполнитель из списка `executor`); when её открывает исполнитель, then видит только свои задачи
- [ ] Given карточка задачи, when её открывает пользователь, then видит поля (название, описание, объект, исполнитель, статус, автор, дата создания), историю статусов (кто, когда, из какого статуса в какой, комментарий) и только кнопки из `getAvailableActions(role, status, isAssignee)`
- [ ] Given задача в `review`, when постановщик нажимает «На доработку», then открывается модалка, и отправить её без комментария нельзя
- [ ] Given задача не в статусе `accepted`, when постановщик открывает её карточку, then может редактировать поля и удалить задачу (soft delete через `delete_task`); в `accepted` карточка только для чтения
- [ ] Given исполнитель, when он открывает «Мои задачи», then видит список своих задач с фильтром по статусу
- [ ] Given `getAvailableActions`, when проверяются все комбинации роли, статуса и назначения, then результат совпадает с матрицей переходов из БД (юнит-тест)
- [ ] Given успешная смена статуса, when RPC возвращает ответ, then статус и история в карточке обновляются без перезагрузки (инвалидация запросов TanStack Query)

## Как делаем
- `AuthProvider` на `supabase.auth.onAuthStateChange` и загрузка профиля с ролью из `profiles`; компонент `ProtectedRoute`; `AppLayout` (Mantine AppShell) с навигацией по роли.
- Маршруты: `/login`, `/objects`, `/objects/:id`, `/tasks/:id`, `/my-tasks`.
- Доступ к данным через хуки TanStack Query поверх `supabase` с типами из `src/types/database.ts`; смена статуса через `rpc('change_task_status')`, удаление через `rpc('delete_task')`.
- `src/lib/taskActions.ts`: чистая функция `getAvailableActions(role, status, isAssignee)`, повторяющая матрицу БД, и подписи статусов на русском.
- Ошибки PostgREST/RPC показываем через Mantine notifications.
