## Что делаем
Готовим демо-стенд для проверяющих: создаём в Supabase тестовых пользователей (1 постановщик, 2 исполнителя), заливаем сиды с объектами и задачами во всех статусах с согласованной историей, отключаем открытую регистрацию и деплоим фронтенд на Vercel. Это первый пункт сдачи из ТЗ (раздел 4).

## Пользователь получает
Как **проверяющий**, я могу **открыть ссылку, войти под любой из трёх выданных учёток и сразу увидеть объекты и задачи в разных статусах**, чтобы **оценить логику без ручной подготовки данных**.

## Готово когда
- [ ] Given Supabase Dashboard, when созданы 3 пользователя (1 manager, 2 executor), then у каждого есть строка в `profiles` с правильной ролью и ФИО
- [ ] Given `supabase/seed.sql`, when он применяется к пустой базе после миграций, then появляются 3 объекта и около 8 задач, покрывающих все статусы (`new`, `in_progress`, `review`, `accepted`, `rework`), распределённых между двумя исполнителями
- [ ] Given задача из сидов, when открывается её история, then цепочка переходов согласована с текущим статусом и матрицей (начинается с `null → new`, у `rework` есть комментарий, `changed_by` — правильная роль)
- [ ] Given Supabase Auth, when кто-то пытается зарегистрироваться через `signUp` с anon key, then получает отказ (signups disabled)
- [ ] Given проект на Vercel, when в настройках заданы только `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, then прод-сборка открывается по ссылке, вход работает, а при обновлении страницы на вложенном маршруте нет 404 (SPA rewrite)
- [ ] Given собранный бандл и репозиторий, when в них ищется `service_role`, then совпадений нет

## Как делаем
- Пользователей создаём вручную в Dashboard (Authentication → Users), их UUID подставляем в `supabase/seed.sql`.
- Сиды выполняются от `postgres` в SQL Editor или через `psql`: в нём нет `auth.uid()`, поэтому триггеры `tasks` нужно учесть. Варианты: вставлять с `session_replication_role = replica`, временно выставлять `request.jwt.claims` под нужного пользователя или вызывать RPC от его имени. Историю вставляем явно и согласованно.
- В `vercel.json` — rewrite всех путей на `/index.html`.
- Signups отключаем в Dashboard (Authentication → Providers → Email → Allow new users to sign up = off) и дублируем в `supabase/config.toml` (`enable_signup = false`).

## Файлы
